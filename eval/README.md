# Evaluation sets and calibration scripts

Test photos whose labels are known **by construction** (a Wikimedia Commons category, a dataset, a copy
made by a script), and the scripts that choose and measure the thresholds of the reused-photo check.
Nobody labels a photo by hand, and no image of an object is generated by an AI. No photo of Dlala's
production or of its members is in any set.

Images never go into git. They live in `artifacts/eval-photos/` at the repository root (git-ignored;
`EVAL_PHOTOS_DIR` overrides it); this folder holds the scripts and the manifests (URL, licence, author,
sha256 of each file). Keep the artifacts folder under 1.5 GB; the scripts stop when the disk has less than
5 GB free. Results: [`../docs/ML_CV.md`](../docs/ML_CV.md).

## Changes from the Dlala copy

These files come from the Dlala API repository (`scripts/eval/photos/` at commit `914a3f8`, and
`calibrate-openimages.py` at `ac4975a`). What changed:

- **Paths.** The Python scripts import the service from `service/app` (it was `vision/app`); artifacts and
  models default to `artifacts/eval-photos` and `artifacts/vision-models` at the repository root. Run
  lines say `eval/` instead of `scripts/eval/photos/`.
- **Configuration.** The calibration scripts read their three starting values (PDQ distance 31, PDQ
  quality 49, 12 inliers, all from published sources) from [`fingerprint-config.json`](fingerprint-config.json)
  instead of the API's `config/photo-checks.json` (`PHOTO_CHECKS_CONFIG` points to another file).
- **`baseline.ts` is not copied.** It ran the API's own review functions (`services/saleAutoReview.ts`) on
  these sets; that code is private. What it measured is described in
  [`../docs/ML_CV.md`](../docs/ML_CV.md#baseline-the-review-before-this-work).
- **Demo library.** `build-vision-manifest.mjs` drew 150 ordinary photos from the Dlala demo library list
  (Commons files). That list is not here: without `DEMO_PHOTOS=<file>` the `demo:` entries already in
  `vision-manifest.json` are kept as they are.
- **Injection phrasings withheld.** `make-injection.mjs` keeps two sample sentences; the evaluation's ten
  phrasings (four languages) and the `text` field of the injection entries are not published, because they
  mirror what the production rule must catch. Regenerated injection images therefore differ from the
  pinned sha256, and `download.mjs` reports them.
- **Emails.** Two Open Images author names held email addresses; they read « (address removed) », and
  `fetch-openimages.py` now scrubs any address-like author name.
- Comments that cite `services/*.ts` or `config/photo-checks.json` name files of the Dlala API.
- The labelling filters of `build-vision-manifest.mjs` (`NOT_GENUINE`, `NAMES_REAL`) read Commons file
  titles to keep the labels clean. They are not the production rules.

## Node part (manifests, downloads, generated copies)

| File | What it does |
|---|---|
| `build-vision-manifest.mjs` | Builds the « objets » set: `vision-manifest.json` and `pairs.json`. Positives and hard negatives per restricted group from Commons categories, personal-data photos and their traps, ordinary objects (1,000 Amazon Berkeley Objects photos and 150 demo-library photos). Downloads each file once to pin its sha256. |
| `make-injection.mjs` | Writes a sentence addressed to an AI onto 10 positive photos with `sharp`, and records them in `vision-manifest.json` with their parent's id. |
| `build-fingerprint-manifest.mjs` | Builds the « empreintes » set: `fingerprint-manifest.json`, 10,000 ABO photos (disjoint from the 1,000 ordinary ones), split into `calibrate` and `measure` halves by a seeded shuffle. |
| `make-transforms.mjs` | Writes the transformed copies (`lib/transforms.mjs`: JPEG quality 50, 50 % downscale, 70 % and 50 % centre crops, 15° rotation, mirror, text overlay, fake classifieds page, 2×2 collage) of every `measure` photo and 1,000 `calibrate` photos, indexed in `<artifacts>/fingerprint/transforms.json`. |
| `download.mjs` | Fetches every file of both manifests into the artifacts folder and checks every sha256; resumes after an interruption; checks the generated files too. |
| `lib/` | Shared code: paths, seeded order, polite downloader (`common.mjs`), Commons API client (`commons.mjs`), ABO (`abo.mjs`), the transforms (`transforms.mjs`). |

```bash
(cd eval && npm install)                 # sharp 0.35.5 (eval/package.json)
node eval/download.mjs                   # the files the committed manifests name
node eval/make-injection.mjs
node eval/make-transforms.mjs
node eval/download.mjs                   # every sha256 checked (the injection images will differ, see above)

# Rebuilding the manifests from the sources (changes them when Commons changes)
node eval/build-fingerprint-manifest.mjs
node eval/build-vision-manifest.mjs
```

## Python part (calibration, phases 1 and 4b)

Each script's header says how to run it: a uv venv from `service/requirements.lock` (the image's exact
lock), the models in `MODELS_DIR`.

| File | What it does |
|---|---|
| `fetch-openimages.py` | Downloads the 4,000 distinct Open Images V7 validation photos (CC BY 2.0) named in `openimages-manifest.json`. The sha256 is of the stored re-encode, so a different libjpeg can change it. |
| `oi_transforms.py` | Makes the 9 copy types in memory (random-position crops, screenshots on varied backgrounds, collages), seeded; nothing is written to disk. |
| `calibrate-fingerprints.py` | Phase 1: the ABO set through the service's modules (PDQ, DINOv2, `/verify`); thresholds from the calibrate half only. Writes `calibration-fingerprints-<date>.md` into the artifacts folder. |
| `calibrate-openimages.py` | Phase 4b: the same on real photos, plus region fingerprints, tiles and the near-identity rule. |
| `fingerprint-config.json` | The three published starting values the scripts read. |

## Rules the scripts follow

- **Selections are seeded** (`SEED` in `lib/common.mjs`): each item's rank is a hash of the seed and its
  key, so a rebuild picks the same files from the same sources.
- **Licences**: Commons files are kept only when public domain, CC0, CC BY or CC BY-SA, and the licence is
  recorded as Commons states it. ABO is CC BY 4.0, credit Amazon.com. Open Images photos are listed by the
  dataset as CC BY 2.0. Derived files (injection, transforms) keep their parent's licence.
- **Politeness**: every Wikimedia request (API and files) takes one shared turn, one at a time, 9 s apart,
  with `maxlag=5` and back-off on 429; at most 4 downloads at a time elsewhere; a generic User-Agent. ABO
  single files only, never its tar archives.
- **Labels by title**: a category file whose title names the opposite of its label (a positive that says
  « replica » or another material; a hard negative that names the real thing) is left out. Nothing is
  judged by looking at the photo.
- **Calibrate and measure never mix**: thresholds are chosen on `calibrate`, reported on `measure`;
  collage fillers come from the same half as the photo.

## Known limits

- Commons can re-render a thumbnail; its bytes then differ from the pinned sha256 and `download.mjs`
  reports it. The `sourceSha1` of the original file is recorded too.
- ABO small images are at most 256 px, the Commons photos 1,280 px: a model can learn size instead of
  content. Calibration should resize every image to the model's input first.
- Some labels stay weak: counterfeit goods often look like the real article; a Roman coin found by a
  detector looks like one sold legally; « synthetic tortoiseshell » frames do not state their material.
- Transforms regenerate byte for byte only with the same `sharp`/libvips and fonts; the files and their
  sha256 in `transforms.json` are the reference.
